## 灰度、几何与yaw的职责

### 半圆 ARC

当前半圆是“几何曲率前馈 + 灰度反馈修正”，不是纯灰度，也不是纯编码器：

1. 半径400 mm和等效轮距160 mm先生成内外轮基础速度。
2. 灰度有效时，`arc_line_kp=0.025`按线位置修正左右轮，修正限幅20 mm/s。
3. 灰度无效时仍按基础圆弧走，避免1 cm细线暂时丢失后立刻失控。
4. ARC按180 deg作为角度兜底；110 deg以后见过有效弧线，再连续丢线5帧，
   可进入150 mm传感器到轮轴补偿并以`LINE`退出。

几何前馈不能直接删除：当探头正好压在线中心时`position=0`，纯P灰度会给
左右轮相同速度，小车反而走直线。后续优化应增加弧线入口捕获和强弱置信度
分级，而不是只把`arc_line_kp`无限加大。

### 矩形 LINE_FOLLOW

灰度有效时由灰度PID主管：

```text
line correction = position * LINEKP
                 + 积分项
                 + 微分项
                 + 限幅15 mm/s的yaw辅助
left  = base + correction
right = base - correction
```

当前`LINEKP=0.025`，I/D为0。灰度无效时才暂时按进入该段时的yaw直行。
因此矩形巡线本身是灰度主导，yaw只负责短暂丢线和小幅稳定。

### 直角触发与转向

每条矩形边走到预计长度75%以后才开放事件，防止途中污点误触发。满足以下
任一证据即可候选：

- `position >= 2000`；或
- 右侧灰度能量占比至少65%，且至少3路有效、有效跨度至少3路；或
- 已经见过线，随后连续丢线3帧。

右角形态需连续2个20 ms控制帧。确认后不立即转弯，而是以80 mm/s保持yaw
再走`CORNERAXLE=70 mm`，让轮轴到达灰度阵列先看到的机械拐点。随后yaw环
执行右转；转过80 deg后，若新线在中心`+-900`内连续`REACQ=2`帧，就由
灰度重捕提前结束转向，否则90 deg角度退出兜底。

## 任务3-1数据结论

CSV共5000行，其中真正任务3为最后两次完整运行，两次均`fault=0`并到达终点。

- 第一次：矩形三边均以`DIST`退出；三段大部分时间为`mask=255`、8路全有效，
  算法看到的是整片黑色，不像右侧拐角，也没有丢线，连续帧改为1不能解决。
- 第二次：矩形三边均以`LINE`退出，两个直角至少一次由`REACQ`结束。
- 直线速度环实测MAE约3~3.5 RPM；弧线约2.3~2.6 RPM，不是当前主因。
- 弧线可靠黑线约在弧内39~48 deg才出现；此前`confidence=204~280`的弱边缘
  也会通过普通`line.valid`，说明弧线入口更需要强弱置信度分级，而非放宽门槛。

## 三圈测试步骤

1. 上电后整车保持静止，等IMU校准完成。
2. 用KEY3依次完成白场、黑场标定，OLED必须显示灰度`OK`。
3. 把车放在A点，车身纵轴沿A->B并朝正东，不再人工斜对C。
4. VOFA+开始保存CSV，先发`PARAMS`记录RAM参数。
5. 按KEY1启动。预期第一动作是原地/单轮右转约38.66 deg，而不是直行。
6. 第一、二圈到A只提示并继续；第三圈到A才停车。异常时按KEY1急停。

本轮不要改PID。重点记录：

- 是否依次进入`SEG01 -> SEG17 -> SEG33`；
- 三次A->C是否都命中C点线；
- 三次半圆何时首次稳定看到黑线；
- 矩形九条边各自以`LINE`还是`DIST`退出；
- 四个右转是否以`REACQ`还是`ANGLE`退出；
- 是否出现`mask=255`持续整段，以及当时车辆相对黑线的位置；
- 最终是否到`SEG49`且fault始终为0。

基线通过标准：完成三圈、无故障、九条矩形边至少8条以灰度`LINE`退出，
并且各圈没有明显扩大横向误差。若仍大量`DIST`，先处理灰度有效性分级、
阵列安装中心和入口捕获，不先加大巡线Kp。
