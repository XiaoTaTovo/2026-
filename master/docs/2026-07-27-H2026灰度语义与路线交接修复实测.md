# H2026 灰度语义与路线交接修复实测

## 这次修复解决什么

本轮针对任务4实测中的三个主故障，不靠继续放大 `LINEKP` 解决：

| 旧现象 | 根因 | 现在的处理 |
|---|---|---|
| 全黑区域也被当作居中黑线，约80度就提前结束转弯 | 旧算法只有 `valid/position`，`mask=255` 的质心也接近0 | 新增 `NONE/NARROW/WIDE/SPLIT`；只有 `NARROW` 能做巡线PID和TURN重捕 |
| 半圆已经到180度，但轮轴补偿可能没走完 | ARC角度退出检查早于 `AXLE_APPROACH` | 轮轴补偿阶段优先，进入后必须走满 `ARCAXLE` |
| 没找到目标线仍按地图距离直接右转 | 距离兜底被当成了转弯授权 | 距离只开启80 mm低速搜索；仍无真实线就停车并报 `0x200` |

旧 `valid/position/mask`、H2024行为和CSV的 `I0-I44` 均保留。新语义分类只在H2026启用。

## 当前控制逻辑

### 窄线识别

每帧先取8路中最小的两路求平均，作为当前局部背景 `bg`。每路减去背景后，
相对差值至少为 `GRAYDELTA` 才作为候选。候选必须满足：

- 总相对置信度至少 `TRACKCONF`；
- 活跃路数不超过 `TRACKMAX`；
- 首末活跃探头跨度不超过 `SPAN`；
- 只能形成一个连续簇。

满足后为 `NARROW`。至少 `WIDEMIN` 路绝对有效、且两路最低背景的平均值仍
达到 `WIDEBG`，才判为 `WIDE`；这样低背景上的真实窄峰不会仅因旧阈值偏低、
`mask=255` 就被误杀。有候选但形态不连续或过宽则为 `SPLIT`；其余为 `NONE`。

### 半圆

半圆仍是“半径/等效轮距前馈为基础，窄线灰度做修正”。进入弧线后至少转过
`ARCENTRYDEG=8 deg`，连续看到 `ARCENTRY=2` 帧窄线才锁定；随后用
`ARCBLEND=200 ms` 把灰度修正从0渐增到100%，避免入口第一帧猛打方向。

110度以后曾稳定见到窄线、随后连续丢线时，先保持弧线走满
`ARCAXLE=150 mm`，再退出ARC。`WIDE/SPLIT`既不能当作弧线窄线，也不能当作
“弧线已经消失”的证据。

### 对角线终点与直角

对角线末端不是“探头一碰线就转”。流程为：

1. 末段捕获窄线；
2. 低速向前，直到线中心进入 `CROSSPOS` 或最多走 `CROSSWIN`；
3. 再走 `DIAGAXLE`，把轮轴送到捕获位置；
4. 才进入下一转向段。

矩形直角只有稳定窄线参与巡线。宽面只有在本段已经见过窄线、并且进入末段
布防区后，才可作为拐角证据。TURN转过80度后只接受窄线重捕；全黑宽面不能
触发 `REACQ`。转完后前 `SETTLEMS=300 ms` 把巡线速度限制为80 mm/s，给灰度
重新锁定的时间。

## 蓝牙RAM调参

先发 `PARAMS` 记录当前全部参数。查询单项只发参数名；修改时在后面加数值，
例如 `GRAYDELTA 140`。修改立即生效，但只保存在RAM，复位或断电恢复宏默认值。

| 命令 | 默认值 | 作用 |
|---|---:|---|
| `GRAYOFF` | 0 | 灰度中心机械偏移；从计算位置中减去该值 |
| `GRAYDELTA` | 120 | 单路相对背景至少高多少才算候选 |
| `TRACKCONF` | 250 | 窄线相对置信度下限 |
| `TRACKIN` | 2 | 连续多少帧窄线后锁定巡线 |
| `TRACKOUT` | 3 | 连续多少帧NONE后认为丢线 |
| `TRACKMAX` | 4 | 窄线最多活跃路数 |
| `SPAN` | 4 | 窄线最大探头跨度 |
| `WIDEMIN` | 6 | 至少多少路绝对有效判为宽面 |
| `WIDEBG` | 600 | 宽面两路最低背景平均值下限，归一化满量程1000 |
| `ARCENTRYDEG` | 8 | 弧线允许锁线前的最小转角，单位deg |
| `ARCENTRY` | 2 | 弧线入口连续窄线帧数 |
| `ARCBLEND` | 200 | 弧线灰度修正渐入时间，单位ms |
| `DIAGAXLE` | 130 | 对角线捕获中心后到轮轴的补偿，单位mm |
| `CROSSPOS` | 1200 | 捕获阶段认为线已接近阵列中心的位置窗口 |
| `CROSSWIN` | 80 | 捕获中心阶段允许的最大前进距离，单位mm |
| `TURNRATIO` | 0.0 | 转弯内轮/外轮速度比；0保持当前单轮支点转向 |
| `SETTLEMS` | 300 | 直角转完后的限速时间，单位ms |
| `SEARCHMM` | 80 | 地图距离到点后仍找线的最大搜索距离，单位mm |

已有 `LINEKP/YAWKP/TURNKP/TURNMIN/ARCAXLE/CORNERAXLE/REACQ/REACQDEG`
以及速度环参数继续保留，未删除。

## 新增VOFA字段

原 `I0-I44` 的数值和顺序不变，只在末尾追加：

| 列 | 名称 | 含义 |
|---:|---|---|
| I45 | pattern | `0=NONE, 1=NARROW, 2=WIDE, 3=SPLIT` |
| I46 | bg | 自适应局部背景 |
| I47 | contrast | 当前最大值减背景 |
| I48 | track_pos | 窄线相对质心，已减 `GRAYOFF` |
| I49 | track_conf | 窄线相对置信度总和 |
| I50 | track_count | 相对阈值命中的路数 |
| I51 | track_mask | 相对阈值掩码 |
| I52 | track_span | 首末候选探头跨度 |
| I53 | clusters | 连续候选簇数，窄线必须为1 |
| I54 | track_locked | 矩形巡线是否已稳定锁定窄线 |
| I55 | track_in | 当前连续窄线帧数 |
| I56 | track_out | 当前连续NONE帧数 |
| I57 | arc_locked | ARC灰度修正是否已锁定 |
| I58 | arc_entry | ARC入口连续窄线帧数 |
| I59 | arc_blend_pm | ARC修正渐入比例，0..1000 |
| I60 | semantic_miss | 必需线路漏检累计次数 |
| I61 | turn_ratio_pm | `TURNRATIO*1000` |
| I62 | settle_active | 转后限速是否生效 |

同时，`I4 phase` 现在为 `0=TRACK, 1=AXLE, 2=CAPTURE, 3=SEARCH`；
`I22 exit` 新增 `5=LINE_MISS`。

## 第一次实测

当前模式仍是 `PROJECT_MODE_H2026_ITEM_4`，OLED应显示 `H26I4`。第一次不要改
任何参数：

1. 整车静止上电，等IMU校准完成；KEY3完成白场、黑场标定。
2. VOFA+开始保存CSV，发一次 `PARAMS`。
3. 车放在A点，车头沿A->B朝正东，按KEY1启动。
4. 正常压窄线时检查 `I45=1`；整片黑面时应为 `I45=2`，且 `I46 bg`
   通常应达到默认 `WIDEBG=600`。若全黑的 `I46` 稳定低于600，再依据CSV下调，
   不要凭单帧直接改。
5. 对角线末端应看到 `I4=2 -> I4=1`，即捕获中心后再做轮轴补偿。
6. ARC进入轮轴补偿后 `I4=1`，`I17 axle_mm` 应增长到约150 mm才换段。
7. TURN期间即使出现 `I45=2` 也不能让 `I22=4`；只有 `I45=1` 可重捕。
8. 若地图距离到点仍没找到线，应进入 `I4=3`；最多80 mm后安全停车，
   `fault=0x200`（CSV十进制 `I23=512`）、`I22=5`，而不是继续盲转。

保存完整CSV。首轮只判断状态序列是否正确；不要同时调参数。若分类有问题，
下一轮按 `GRAYDELTA -> WIDEBG -> GRAYOFF -> DIAGAXLE -> CROSSPOS/CROSSWIN` 的顺序，
每轮只改一个变量。
