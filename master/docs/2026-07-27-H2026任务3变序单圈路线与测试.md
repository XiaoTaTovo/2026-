# H2026 任务3变序单圈路线与测试

## 当前实现范围

任务3已作为独立编译模式 `PROJECT_MODE_H2026_ITEM_3` 实现，路线顺序严格对应题面：

```text
A -> C -> B -> D -> 矩形左下角 -> 矩形左上角 -> A
```

当前版本固定从A点正向起步：车头沿A->B朝正东，程序先右转38.6598度再对准C，不再要求人工斜着摆车。题面要求的二维码自动识别“2/3”、LED闪烁次数和任务2/3自动选择尚未接入，不能把本次路线测试当成二维码要求已经完成。

## 几何来源

A到C、B到D都是100 cm x 80 cm矩形的对角线：

```text
diagonal = sqrt(1000^2 + 800^2) = 1280.6248 mm
angle = atan(800 / 1000) = 38.6598 deg
```

任务3从C到B沿半圆反向行驶，所以该弧线是左转：半径`+400 mm`、角度`180 deg`。当前yaw约定仍为左正右负。

任务3的半圆后面还有SEG07转向，因此SEG05明确关闭了任务2专用的“ARC切线直接交给下一直线”锁存，避免SEG08被错误拉回正西方向。

## 摆车方法

1. 以A->B方向为0度，车头沿A->B朝正东，不再人工偏38.66度。
2. 车辆中心投影覆盖A；记录灰度阵列、轮轴和车体中心分别落在A点的什么位置，后续固定同一摆法。
3. 启动后第一动作必须是程序右转38.66度，随后才进入A->C直线。

## 分阶段测试

### 第一次：只验收A->C和C点转向

烧录后确认OLED为`H26I3`，发：

```text
PARAMS
CORNERAXLE 70
```

运行到`SEG05`刚开始就发`STOP`。应看到：

- `SEG01`先从正东右转38.66度；
- `SEG02`沿对角线稳定直行；
- C点以`LINE`或`DIST`退出并提示一次；
- `SEG04`为正38.66度左转；
- 进入`SEG05`时yaw相对发车约为`0 deg`。

若C点之前提前停车，先看`SEG01`退出原因和触发掩码；若到C后转错方向，不调PID，直接检查SEG03的yaw正负。

### 第二次：只验收C->B左半圆

允许跑到`SEG07`后发`STOP`。重点看：

- `SEG05`右轮目标速度高于左轮，yaw持续增大约180度；
- 车体投影不能明显脱离黑色圆弧；
- B点退出后进入`SEG07`，不能继续多绕弧线；
- SEG05的退出原因、弧长、yaw变化和灰度丢线帧数完整保存。

任务2验证的是右半圆，任务3的左半圆是新工况；第一次不同时修改`ARCAXLE`、弧线Kp和等效轮距。

### 第三次：验收B->D和矩形入口

允许跑到`SEG11`后发`STOP`。重点看SEG07左转38.66度后，SEG08是否沿第二条对角线到D；SEG10必须右转38.66度，使灰度阵列能够接到D点向左的黑线。

### 第四次：完整单圈

前三阶段方向和切段都正确后才完整跑到SEG16。完整任务限时50秒，初期先以无错段、覆盖A/B/C/D和提示次数正确为验收，不先追求时间。

## 输出与实时性

- UART继续使用TX中断环形队列和硬件FIFO，CSV仍为45列原顺序。
- OLED仍为固定精简单页，250 ms重绘、每5 ms只发送一页；只新增`H26I3`模式名，没有新增滚动页或阻塞输出。
- 动态调参仍为RAM值，`STOP`可在任何阶段中止；不要通过拔电源代替正常停止。

## CCS模式文件被旧编辑页覆盖时

如果已经选择任务3但烧录后OLED仍显示`H26I2`，先检查磁盘上的`project_mode.h`，必须同时满足：

```c
#define PROJECT_MODE_H2026_ITEM_3 (9)
#define PROJECT_MODE PROJECT_MODE_H2026_ITEM_3
```

CCS/Theia长时间打开的旧编辑页可能在保存时覆盖外部工具刚写入的磁盘版本。本次实测中，旧页在18:59:46把模式恢复成ITEM2，随后18:59:50构建出的`.out`也确实是任务2。处理方法是关闭并重新打开该文件，或用编辑器的“Revert File/从磁盘重新加载”读取磁盘内容，确认上面两行后再Build；不要再次保存截图中的旧内容。

当前默认构建已经切到任务4三圈；若要单独复测任务3，必须先把`PROJECT_MODE`
切回`PROJECT_MODE_H2026_ITEM_3`并重新Build，不能继续使用旧SHA固件。
